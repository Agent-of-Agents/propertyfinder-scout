# HANDOFF — агент **Scout Dubai** для фабрики

Спецификация для переноса рабочей системы подбора недвижимости в Telegram-бота
на сервере. Этапы 0–3 закрыты и проверены на живом клиенте: от брифа до PDF на
Google Диске. Этап 4 — та же логика без команды с компьютера: бриф голосом
в Telegram, ежедневный прогон, дайджест утром, одобрение кнопкой, PDF в чат.

Редакция 2 от 11.09.2026, дополнена 12.09.2026 (§5.18–5.20: карта DLD, дубли, серия). Отменяет редакцию 1 («Scout Dubai Secondary» +
«Scout Dubai Offplan»): **агент один**, а рынки — это свойство подбора, не агента.

В архиве рядом — `lib/` (рабочие модули), `scripts/` (оркестратор прогона, PDF,
планировка, офф-план), `assets/` (шрифты, шаблон), `requirements.txt`,
`.env.example`, пример карточки клиента. Секретов в архиве нет: ключ сервисного
аккаунта и токен бота передаются отдельно.

## 0. Ответы на вопросы фабрики

**Инструменты ходят во внешние источники или работают с локальными файлами?**
Во внешние, по HTTP, **без браузера**:

- Property Finder, объявления — данные лежат в самой странице, в блоке
  `<script id="__NEXT_DATA__">`. Обычный `urllib` с User-Agent, пауза 1,2 с между
  страницами. Ключей нет, явных лимитов нет, капчи за три дня не встречали.
- Property Finder, проекты застройщиков — раздел «New projects», тот же
  `__NEXT_DATA__`, ~1 100 проектов по Дубаю, кэш карточек на томе.
- Дистресс — три публичных URL (HTML-сайт, CSV-экспорт Google-таблицы,
  веб-зеркало Telegram-канала `t.me/s/…`). Без ключей.
- Google Sheets / Drive — сервисный аккаунт, JSON-ключ. Без OAuth и без человека.

Локальные файлы — только состояние (карточки, выгрузки, фото для PDF), всё это
на томе контейнера. **Значит, всё едет в контейнер.**

Не едут и не должны: Москва (Циан, Яндекс — только живой Chrome с капчами,
этап 5, ПК) и отправка WhatsApp (руками с телефона; у WhatsApp Business нет API,
бот только готовит ссылку — §5.10).

**Интерфейс — Telegram-бот в контейнере?** Да. Но не личный чат, а **закрытая
группа с темами (forum topics)**: тема на клиента — см. §7. Токен от @BotFather
и Telegram ID Алексея передадим отдельно. Бот отвечает **только** ID из
`ALLOWED_TG_IDS` и только в группе `GROUP_ID`, остальным молчит.

**Деплой.** Хост даст Алексей (VPS в ЕС, Ubuntu 24.04, Docker). SSH-ключ и адрес —
отдельным сообщением, когда сервер будет.

**Что важно, чтобы не переписать зря.** `lib/` — чистый Python (`urllib`,
`google-api-python-client`, `fpdf2`, `Pillow`), без фреймворков и без привязки
к Claude Code. Это **готовые реализации инструментов**, а не обвязка. Правильная
стратегия — обернуть функции `lib/` в фабричные tools, а не переписывать парсинг:
там накоплены правила из семи реальных ошибок (§8), повторять их с нуля дорого.

## 1. Модель: клиент → подбор → объект

Единица работы — **клиент**, человек. У него может быть несколько **подборов**
одновременно и они могут быть с разных рынков: вторичка в одном районе, вилла
в другом, два офф-плана от застройщика. Подборы открываются, закрываются и
заменяются, пока клиент жив как сделка. Внутри подбора — **объекты**.

```
Клиент   Иванова Мария · статус active · одна книга · одна папка · одна тема в Telegram
 ├ Подбор  «Marina Shores 2BR»        market=secondary · PF башня · 3–4,5 млн · вид на воду
 ├ Подбор  «Downtown 1BR»             market=secondary · PF район · до 2,5 млн
 └ Подбор  «Off-plan Business Bay»    market=offplan   · каталог PF · до 3 млн · сдача ≤ 2028
      └ Объект  строка листа, якорь listing_id
```

| Уровень | Что это | Где живёт | Стабильный ключ |
|---|---|---|---|
| Клиент | человек и сделка | `client.json`, книга Google, папка Диска, тема Telegram | `client_slug` — `ivanova` |
| Подбор | один запрос: рынок + источники + фильтры + срок | `search.json`, **лист в книге клиента**, `state.json`, папка на Диске | `search_slug` — `marina-shores-2br` |
| Объект | объявление или «проект × тип» | строка листа | `listing_id` — `PF-141439708` или `12345:2BR` |

**Рынок (`market`) — поле подбора.** Два значения сейчас: `secondary`
(объявления PF, брокеры, WhatsApp, PDF по объекту) и `offplan` (проекты
застройщиков, скоринг, платёжные планы). Каждому рынку — свой комплект
инструментов и своя шапка листа (§6). Агент один, он выбирает комплект
по `market` подбора.

**Правила жизни подбора:**

- Клиент передумал → **старый подбор закрывается, новый открывается.** Подбор
  не редактируется задним числом: состояние сверки привязано к источнику
  и фильтру, одобренные строки с PDF стали бы сиротами, и история показанного
  потерялась бы. Бот всегда предлагает две кнопки — «Заменить» (закрыть старый)
  и «Добавить параллельно» — и молча не делает ни того, ни другого.
- Закрытый лист **не удаляется**: переименовывается в `✕ Marina Shores 2BR`
  (или `✓ …`, если куплено), ярлык серый, лист уезжает в конец книги.
  Одобренные объекты и PDF в нём остаются.
- Статусы подбора: `active` → `paused` → `closed` с причиной `bought | replaced
  | dropped`. Прогон идёт только по `active`.
- Все подборы клиента закрыты → клиент `archived`: прогона нет, книга и тема
  остаются, тема закрывается (`closeForumTopic`).

## 2. Роль и системный промпт

```
Ты — Scout Dubai, ассистент брокера Алексея Широкова по подбору недвижимости
в Дубае: вторичный рынок и проекты застройщиков. Работаешь только с Алексеем,
в закрытой Telegram-группе, где на каждого клиента заведена отдельная тема.

Единица твоей работы — клиент. У клиента несколько подборов, каждый — со своим
рынком, фильтрами и листом в его книге. Ты ведёшь их все и держишь актуальными
каждое утро без напоминаний.

Что ты делаешь сам:
- принимаешь бриф нового клиента (текст или голос) в общей теме, уточняешь
  недостающее одним сообщением, заводишь клиента: карточку, папку, книгу,
  тему в группе — и первый подбор;
- принимаешь новый подбор у существующего клиента в его теме; если он похож
  на замену существующего — спрашиваешь: «Заменить» или «Добавить параллельно»;
- по подбору secondary собираешь объявления Property Finder по проекту или
  району; по подбору offplan — проекты застройщиков из каталога PF со скорингом;
- каждое утро сверяешь все активные подборы с рынком: новые, изменения цены,
  снятые, дистресс под бриф; пишешь сводку в общую тему и подробности — в тему
  каждого клиента, у которого что-то изменилось;
- по кнопке показываешь карточки объектов; по команде Алексея одобряешь объект
  с его ценой и собираешь PDF; готовишь WhatsApp-ссылку брокеру — отправляет
  Алексей сам; принимаешь планировку от брокера фото в теме и пересобираешь PDF;
- отвечаешь на вопросы по клиенту и его подборам — только из данных таблиц.

Адресация:
- сообщение в теме клиента относится к этому клиенту; если у него несколько
  активных подборов и команда неоднозначна — спроси кнопками, не угадывай;
- ответ (reply) на карточку объекта относится к этому объекту;
- сообщение в общей теме без имени клиента при нескольких активных — спроси,
  о ком речь;
- каждое твоё сообщение о конкретном объекте начинается со строки
  «Клиент · Подбор».

Правила, которые не нарушаются:
1. Цена в презентацию — только та, что назвал Алексей. Из объявления — никогда.
2. В колонки Алексея («✅ Одобрено», «📩 Запросить», «Статус», «Моя цена»,
   «Мой комментарий») пишешь только по его явной команде в чате — кнопка или
   ответ на твой вопрос. Ежедневный прогон их не трогает.
3. Строки и листы не удаляются. Снятый объект — серая заливка и зачёркивание;
   закрытый подбор — переименованный серый лист в конце книги.
4. Клиент не видит контактов, логотипов и следов площадки. В PDF — только объект.
5. Цену ниже рынка называешь прямо — это аргумент. Выше рынка — не комментируешь.
6. Вид и этаж — из заголовка объявления; описание — только запасной источник.
7. Русскоязычные брокеры — приоритет, всегда сверху, отдельный признак.
8. Источник недоступен (403, капча, таймаут) — не гадаешь: одно сообщение
   в общую тему, повтор по расписанию.
9. Ничего не отправляешь третьим лицам. Отправляет Алексей.
10. Между 22:00 и 08:00 по Дубаю не пишешь ничего, кроме отказов источников,
    если прогон был перенесён на это время.

Язык — русский, коротко, без воды. Цифры с разделителями тысяч, валюта AED;
USD по 3,6725 — только в презентациях.
```

## 3. Что хранится между сессиями

Том `/data`. Раскладка — под модель §1; `lib/` работает без правок, меняется
только оркестратор (`scripts/daily.py` читает подборы вместо одного брифа).

```
/data/clients/<client_slug>/
    client.json            имя, контакт, статус, spreadsheet_id, drive_folder_id,
                           telegram_topic_id, created, deadline (дата сделки/приезда)
    brief.md               бриф человеческим языком + выводы по рынку, дописывается
    searches/<search_slug>/
        search.json        market, название листа, источники (URL PF или блок
                           offplan — схема в докстринге lib/offplan.py), фильтры
                           (спальни, бюджет, тип), пожелания, стоп-лист, статус,
                           причина закрытия, даты
        state.json         состояние сверки: listing_id → first_seen, last_seen,
                           цена, заголовок, агент, missed_days
        raw/               последняя сырая выгрузка
        approved/<listing_id>/   фото, планировка, detail.json, PDF
        requests.json      запросы брокерам: listing_id → дата
/data/pf_projects/         каталог проектов застройщиков: список на дату,
                           details/<id>.json, projects.json (общий на всех клиентов)
/data/distress_seen.json   ключи уже показанных дистресс-предложений
/data/panel.json           spreadsheet_id книги «Панель» (§6.5)
/data/tg_map.json          callback_data → (client, search, listing) — если
                           не помещается в 64 байта callback_data напрямую
```

Пример `client.json` и `search.json` — в архиве, `clients/example/`.
Если фабрике удобнее Postgres — ок, `client.json`/`search.json`/`state.json`
становятся таблицами, `lib/sync.py` получает адаптер `load_state/save_state`
(две функции). Каталог проектов (`pf_projects/`) лучше оставить файлами — это кэш.

## 4. Источники данных

| Источник | Как | Ключи / лимиты |
|---|---|---|
| PF, объявления (secondary) | GET страницы башни или района `…/apartments-for-sale-dubai-marina-marina-shores.html`, `__NEXT_DATA__`, пагинация `?page=N`. **Текстовый поиск не использовать** — PF игнорирует его и отдаёт все 120 тыс. объявлений | Нет ключа. UA обязателен. Пауза 1,2 с. ~10 стр. на башню |
| PF, карточка объявления | GET → все фото, `floor_plans`, `contact_options` (WhatsApp), `similar_price_transactions` (сделки DLD) | То же |
| PF, проекты (offplan) | `/en/new-projects/lp/dubai`, `__NEXT_DATA__`: застройщик, район, фаза продаж, старт продаж, сдача, платёжный план, цена «от» по типам, сделки DLD по локации. Кэш карточек, перечитывается при смене цены/фазы/сдачи или раз в 14 дней | Первый сбор ~45 мин, дальше 5–10 мин. Один раз за прогон на всех клиентов |
| distressonly.deals | GET HTML, регулярки: OP+DLD, Selling price, Discount % | Нет |
| Google-таблица офф-плана | CSV-экспорт публичной таблицы, метки NEW / NEW PRICE | Нет |
| t.me/distress_deal | веб-зеркало `https://t.me/s/distress_deal`, без бота | Нет |
| Google Sheets + Drive | сервисный аккаунт `claude-sheets@podbor-obyektov.iam.gserviceaccount.com`, scopes spreadsheets + drive | JSON-ключ через `GOOGLE_APPLICATION_CREDENTIALS` |

**Ограничение Google, ломающее автономию, если забыть.** У сервисного аккаунта
нет хранилища: файл, созданный им в «Мой диск», получает `403 storageQuotaExceeded`.
На сервере и книги, и PDF создаются **на Общем диске** (`supportsAllDrives=True`
уже стоит во всех вызовах `lib/drive.py`). `DRIVE_FOLDER_ID` — папка Общего
диска, где у сервисного аккаунта роль «Менеджер контента».

## 5. Инструменты

Функции уже есть в `lib/` и `scripts/`; в скобках — что оборачивать.
Инструменты с пометкой **[S]** — только для подборов `secondary`, **[O]** —
только `offplan`, без пометки — общие.

### 5.1 `intake_parse(text, client=None) → brief`
LLM по схеме. Из текста или расшифровки голоса — бриф: если `client` не задан,
это новый клиент **и** его первый подбор: `{client:{name, contact, deadline,
notes}, search:{market, title, project|locations, bedrooms, budget, readiness,
wishes, stop}}`. Если задан — только `search`. `market` определяется по словам
(«у застройщика», «пресейл», «рассрочка», «сдача 2028» → offplan; башня, «вторичка»,
«перепродажа», конкретный лот → secondary); если неясно — вопрос кнопками
«🏠 Вторичка / 🏗 От застройщика». Обязательное: имя (для нового клиента),
рынок, локация или проект, спальни, бюджет. Недостающее — один уточняющий вопрос.

### 5.2 `client_create(brief.client) → client`
(`lib/client_folders.ensure_client_tree`, `lib/drive.create_spreadsheet_in_folder`,
`lib/sheets.*`, Telegram `createForumTopic`.) Папка клиента на Общем диске,
книга с листами «Сводка», «Дистресс», «Лог» (шапки — §6), тема в группе с именем
клиента. `client.json` на том. Возвращает клиента с `topic_id`.

### 5.3 `search_create(client, brief.search) → search`
Лист в книге клиента с шапкой по `market` (§6.2 / §6.3), чекбоксы, закреплённая
строка, папка подбора на Диске, `search.json`, строка в «Сводке» и в «Панели».
Затем первый сбор: `pf_collect` + `sheet_sync` для secondary, `offplan_pick`
для offplan; затем `distress_check`. Возвращает сводку первого сбора для карточки
в тему.

### 5.4 `search_close(client, search, reason)` · `search_replace(client, old, brief) → search`
Закрытие: статус, переименование листа в `✕ …` / `✓ …` (reason=bought), серый
ярлык (`tabColor`), перенос листа в конец (`updateSheetProperties.index`),
обновление «Сводки» и «Панели». Замена — `search_close(old, "replaced")` +
`search_create(new)`.

### 5.5 `pf_collect(base_url, max_pages=10) → listing[]` **[S]**
(`lib/propertyfinder.collect`) Нормализованные объявления: `id (PF-123), url,
title, building, location, type, bedrooms, bathrooms, size_sqft, size_m2, price,
price_per_m2, completion, furnished, water_view, agent_name, agent_languages,
agent_url, ru_score (0–3), ru_reason, agency, agency_phone, agency_email,
verified, images_count, listed_date, reference`.
`ru_score`: 3 — в профиле агента указан Russian; 2 — славянское / среднеазиатское
имя или фамильное окончание; 1 — русский текст в объявлении; 0 — нет признаков.

### 5.6 `pf_detail(url) → detail` **[S]**
(`lib/listing_detail.fetch_detail`) Полная карточка: фото, размеченные
`floor_plans`, описание, удобства, `similar_price_transactions`, свежая
WhatsApp-ссылка. `download_images(urls, target)` — до 12 фото на том.

### 5.7 `sheet_sync(search, fresh) → report` **[S]**
(`lib/sync.run`, фильтр `fits_search`: тип из брифа, цена ≤ max × 1,05 — из
`scripts/daily.py`.) Единственный инструмент, пишущий в лист secondary без команды:
- новый → строка **сверху**, голубая заливка, `🆕 дд.мм`; снимается через 3 дня
  или при любой галочке;
- цена изменилась → оранжевая заливка, `💰 было → стало`;
- заголовок изменился → пересчёт вида/этажа; агент сменился → брокер и балл 🇷🇺,
  порядок строк не трогать;
- пропал **два дня подряд** → серая заливка, зачёркивание, `⚰️ снято`;
  одобренный пропал — отдельно в отчёт;
- колонки Алексея не трогать, строки не удалять, не сортировать.

Пишет **по названию колонки**, сверяя заголовок целевой ячейки перед записью;
не совпал — стоп до первой записи. Якорь — скрытая колонка A `listing_id`.
Возвращает `{new[], price[], title[], agent[], removed[], approved_removed[], medians}`.

### 5.8 `offplan_catalog_refresh() → stats` **[O]**
(`lib/pf_projects`, `scripts/offplan_market.py`.) Один раз за прогон, если есть
хоть один активный подбор offplan. Обновляет `/data/pf_projects/projects.json`
и книгу «Off-plan Дубай — каталог PF» на Общем диске.

### 5.9 `offplan_pick(search) → report` **[O]**
(`lib/offplan.build_rows` + `lib/offplan_sheet.sync`.) Фильтр по блоку offplan
подбора, объясняемый скоринг 0–100 (цена за м² против медианы района по типу
и против сделок DLD, стадия — пресейл плюс, взнос и post-handover, срок сдачи;
причины в «Комментарий системы»; веса в `lib/offplan.score`, правятся по отзывам
Алексея). Сверка листа по `listing_id = project_id:тип` с теми же правилами
заливки; отслеживаемые колонки: «Цена от AED», «Фаза продаж», «Сдача», «План оплаты».

### 5.10 `distress_check(client) → match[]`
(`lib/distress.collect_all`, `matches`, `write_new`.) Три источника, совпадение
с ключевыми словами и бюджетом **всех активных подборов клиента**, новые строки —
в лист «Дистресс» с колонкой «Подбор». Новые совпадения — в тему клиента с 🔥.

### 5.11 `whatsapp_link(listing_url) → {link, phone, text} | None` **[S]**
(`lib/whatsapp.gateway_link`.) Тянет страницу заново — в тексте цена и reference,
они меняются. **Текст менять нельзя**: PF предупреждает, что изменённое сообщение
до агента не дойдёт. Бот отдаёт URL-кнопкой «💬 Открыть WhatsApp» и кнопкой
«✔ Отправил» — по ней дата ложится в «Запрошено».

### 5.12 `sheet_mark(search, listing_id, column, value)`
(`lib/sheets.update_ranges` + `guard_write` из `scripts/make_presentation.py`.)
Запись в **колонку Алексея** — только из обработчика кнопки или явного ответа.
Разрешённые: «✅ Одобрено», «📩 Запросить», «Моя цена», «Статус». Прогон этот
инструмент не вызывает.

### 5.13 `pdf_build(search, listing_id, price) → {pdf_path, drive_link}` **[S]**
(`scripts/make_presentation.make` — вынести в `lib/`; `enrich`, `build_comment`,
`unit_folder`, `upload_to_drive` уже модульны.) Белая вёрстка 16:9, английский:
обложка, описание, галереи всех фото объявления (сетки чередуются), планировка
отдельным листом, заключение с ценой AED и USD. Файл `marina_shores_2br_105sqm.pdf`
в папке подбора; пересборка **обновляет файл на месте**. Ссылка — в «Презентация»,
файл — в тему клиента.
Фото по приоритету: `photos_custom/` → все фото объявления → рендеры проекта
из `assets/projects/<проект>/`, только если в объявлении меньше 8. Планировка —
только размеченная; догадка детектора в PDF не попадает без подтверждения.
Шрифты Montserrat в архиве; **Calibri из `C:/Windows/Fonts` в контейнере нет** —
заменить на любой sans в `lib/pdf_brochure.py:81-82`.
PDF по проекту offplan — позже, отдельной задачей.

### 5.14 `attach_plan(client, hint, image, as_photo=False) → {pdf_path, drive_link}` **[S]**
(`scripts/attach_plan.py`.) Фото планировки в теме клиента с подписью-зацепкой
(брокер, агентство, телефон, ссылка, цена) или как reply на карточку объекта.
Ищется среди одобренных, потом по всем листам клиента. Файл в `approved/<id>/`,
PDF пересобирается.

### 5.15 `sheet_query(client, question) → rows`
(`lib/sheets.read_range` по всем активным листам клиента + фильтр LLM по схеме
колонок.) Для вопросов свободным текстом. Ответ — только из данных, каждая строка
со ссылкой и именем подбора.

### 5.16 `panel_update()`
Книга «Панель» (§6.5): строка на каждый подбор всех клиентов. Вызывается после
`search_create/close`, после каждого прогона и после каждого одобрения.

### 5.17 `daily_run(client=None) → report`
(`scripts/daily.py` — готовый оркестратор, сегодня его запускает Планировщик
Windows в 09:00 МСК; после переезда задание там отключить.) Порядок:
1. `offplan_catalog_refresh()` — если нужен;
2. по каждому клиенту `active`, по каждому подбору `active`: secondary →
   `pf_collect` → `sheet_sync`; offplan → `offplan_pick`;
3. `distress_check(client)`;
4. новые галочки ✅ с ценой → `pdf_build`;
5. «Сводка» клиента, лист «Лог», `panel_update()`;
6. возвращает отчёт по клиентам → подборам — из него бот собирает сообщения §7.4.

Планировщик в контейнере (APScheduler или cron): 08:00 по Дубаю. Это
**проактивные** сообщения — обвязка должна уметь писать в группу по таймеру,
в нужную тему (`message_thread_id`).

### 5.18 `dld_card(listing_url) → card | None` **[S]**
(`lib/trakheesi.parse_card`; накопитель `data/dld_cards.json` — повторно не
пробивать.) По `rera.permit_validation_url` объявления открыть карту разрешения
DLD Trakheesi и снять с неё: **точную площадь до сотых**, **личный мобильный и
email агента**, номер и срок разрешения, лицензию агентства. Номера юнита в
карте **нет**.
Карта отдаётся только браузеру (reCAPTCHA v3 на `b2c.dubailand.gov.ae`):
в контейнере — headless Chromium (Playwright): открыть → 4 с → `button.btn-close`
→ 2,5 с → `body.innerText` от «Real Estate Permit Card». ~8 с на объект, поэтому
только для одобренных, запрошенных и топ-N подбора — это гос-сервис, всю выдачу
не дёргаем. Капчу не обходим: если карта не открылась — «карта DLD недоступна»
и повтор на следующем прогоне.

### 5.19 `dupes(search, listing_id) → group` **[S]**
(`lib/trakheesi.fingerprint`, `find_duplicates`; подтверждения по фото —
`data/dld_dupe_confirm.json`.) Группа объявлений на **одну квартиру**:
здание + площадь DLD до сотых. Внутри группы — по строке на объявление:
цена, брокер, агентство, дата появления, 🇷🇺, ссылка, телефон DLD.

**Две ступени уверенности, обе показываются как есть:**
- **✔ одна квартира** — совпал номер разрешения DLD (один агент выставил
  дважды) или общие фото (dHash первых 6 кадров, ≥ 2 совпадения);
- **≈ похоже, одна квартира** — площадь до сотых та же, фото разные.
  В башне такая площадь — по одной на этаж, так что это либо та же квартира
  у второго брокера (норма в Дубае), либо соседняя по стояку. Бот так и
  пишет: «уточнить этаж у брокера». Выше ступень не поднимаем — это честно.

Для off-plan фото — рендеры застройщика, признак слабый: группа остаётся на
ступени ≈.

### 5.20 `series(listing) → label` **[S]**
(`lib/layout.extract` / `label`, `scripts/enrich_series.enrich`, кэш описаний
`raw/details.json`.) Серия / тип планировки из заголовка и описания:
`BEST LAYOUT 07`, `* 04 Series`, `Type C`, `10th series`, `Unit 2304`.
Есть у ~10 % объявлений, ложных срабатываний нет — что нашлось, то и в колонке
«Серия»; нет — прочерк, не гадать.

**Номер юнита.** Точный номер квартиры ни PF, ни карта DLD не дают. Его можно
получить только сопоставлением площади с реестром юнитов здания
(`data/dld_units/<здание>.csv` → `trakheesi.match_unit`), и результат — это
1–3 кандидата по стояку, точный только вместе с этажом. Реестр: open-data DLD
(`dubailand.gov.ae/en/open-data/real-estate-data/#unit`) на 12.09.2026 отдаёт
пустой `result` по любому фильтру, при рабочих сделках с того же IP; Dubai Pulse
`dld_units-open` из России не открывается. Пока реестра нет — колонка
«Юнит DLD» = «реестра здания нет», бот номер не называет и не придумывает.

## 7. Telegram: группа с темами

### 7.1 Устройство
Одна закрытая супергруппа «Scout Dubai» с включёнными темами (forum). Участники:
Алексей и бот (бот — администратор с правом управлять темами). Бот проверяет
`chat.id == GROUP_ID` и `from.id ∈ ALLOWED_TG_IDS`, иначе молчит.

- **General** — общая тема: утренняя сводка по всем клиентам, новые брифы,
  `/clients`, `/panel`, отказы источников.
- **Тема клиента** — создаётся `createForumTopic` при `client_create`, имя —
  фамилия и имя, `icon_color` любой из допустимых. Всё про клиента живёт здесь:
  дайджест по его подборам, карточки, PDF, вопросы Алексея, планировки.
  Закрытие клиента → `closeForumTopic`, тема остаётся в архиве.

### 7.2 Адресация
- Сообщение в теме клиента → этот клиент. Несколько активных подборов и команда
  без имени подбора → вопрос кнопками с именами подборов.
- Reply на карточку объекта → этот объект (по `message_id` → `tg_map`).
- Сообщение в General без имени клиента при нескольких активных → вопрос
  кнопками с именами клиентов.
- Каждое сообщение бота об объекте начинается строкой **«Клиент · Подбор»**:
  дублирование адреса нужно, потому что Telegram умеет показывать все темы одной
  лентой, и там без тега карточки неразличимы.

### 7.3 Кнопки
`callback_data` ≤ 64 байт: `a|<client>|<search>|<listing>` с короткими
кодами (`ap` одобрить, `rq` запросить, `sk` пропустить, `st` отправил,
`rp` заменить, `ad` добавить, `cl` закрыть, `pg` страница). Не помещается —
ключ в `tg_map.json`. URL-кнопки: таблица, папка, WhatsApp, Панель.

Стандартные наборы:
- под карточкой secondary: `✅ Одобрить · 📩 Запросить · 🔎 Дубли · ⏭`
  (🔎 — только если у объекта есть группа §5.19; в подписи карточки тогда
  строка «🔎 ещё 2 объявления этой квартиры, от 3 650 000»)
- под группой дублей: `💬 Написать <брокер> (URL wa.me, телефон DLD)` на каждого
  · `✅ Одобрить дешевле` · `📊 Лист «Дубли» (URL)`
- под карточкой offplan: `✅ Одобрить · 📄 Брошюра (URL, если есть) · ⏭`
- под запросом брокеру: `💬 Открыть WhatsApp (URL)` / `✔ Отправил · ✖ Передумал`
- под новым подбором у существующего клиента: `🔁 Заменить «…» · ➕ Добавить параллельно · ✖ Отмена`
- под брифом нового клиента: `✅ Запустить · ✏️ Поправить`
- под сводкой: `🆕 Показать новые · 💰 Цены · 📊 Книга (URL)`
- под `/clients`: `⏸ Пауза · ✔ Куплено · ✕ Закрыть · ➕ Подбор`

### 7.4 Что бот пишет сам и когда
| Когда | Куда | Что |
|---|---|---|
| 08:00 Дубай, после прогона | General | одна строка на клиента: `Иванова · 🆕 3 · 💰 2 · ⚰️ 1 · 🔥 1`; клиенты без изменений — одной строкой «без изменений: Гареев, Ким» |
| 08:00, следом | тема каждого клиента с изменениями | по подборам: что нового, что подорожало/подешевело, что снято; кнопки «Показать новые» |
| сразу при прогоне | тема клиента | ⚠️ одобренный объект снят — отдельным сообщением, потому что PDF мог уйти клиенту |
| сразу | General | ⚠️ источник недоступен, когда повтор |
| после «Запустить» / нового подбора | тема клиента | сводка первого сбора: объектов, 🇷🇺, в бюджет, медиана, дистресс, вывод по рынку |
| после одобрения с ценой | тема клиента | PDF файлом + ссылка |
| после одобрения, если у объекта есть дубль | тема клиента | группа дублей §5.19 — сразу под сообщением о PDF: «эту же квартиру продают ещё N, дешевле на …» |
| 08:00, в дайджесте подбора | тема клиента | строка «🔎 дубли: у 2 одобренных есть объявление дешевле» — только когда появилось новое |
| за 7 и за 2 дня до `deadline` | тема клиента | напоминание: сколько одобрено, сколько презентаций, что не запрошено |
| 22:00–08:00 | — | тишина |

### 7.5 Команды
`/new` — бриф нового клиента (или просто голосовое в General) · `/clients` —

## 8. Уроки, зашитые в код — не потерять при переносе

| Что случилось | Правило теперь |
|---|---|
| Запись по номеру колонки затёрла цены Алексея после вставки двух колонок | Колонки только по названию; сверка заголовка перед записью; отказ, если колонка чужая |
| Две презентации на одних рендерах | Фото объявления — основной источник, рендеры только дополняют |
| Планировка попала в галерею под другим именем | Исключение по хешу содержимого |
| Детектор принял ванную за чертёж | Догадка — на подтверждение, в PDF только размеченное |
| Каждая пересборка — новый файл, ссылка протухала | Файл обновляется на месте |
| «Priced above the tower average» ушло клиенту | Выше рынка не комментируем |
| Объявление за полдня сменило заголовок и вид | Ежедневная перепроверка; вид из заголовка, не из описания проекта |
| Сверка полной выдачи башни против листа под 1–2BR → 31 ложный «новый» | Фильтр `fits_search` по типу и бюджету перед сверкой; медиана — по всей башне |
| «Пропал два раза подряд» считалось по запускам → два ручных прогона за вечер пометили «снято» | Считается по дням |
